# Тестирование

## Уровни проверки
| Уровень | Команда | Что проверяет |
|---|---|---|
| Типы и структура | `npm run typecheck` | TypeScript strict по всему коду, тестам и конфигам |
| Unit (Vitest, Node) | `npm test` | рантайм сценария, условия и эффекты, сохранения (повреждённые данные, переполнение хранилища), **правила всех 5 мини-игр** (достижимость платформ, интервалы препятствий, решение головоломок), **валидация сценария** и **обход всех путей сюжета**: все 3 концовки достижимы, тупиков нет |
| Сборка | `npm run build` | production-сборка; отсутствующий импортируемый ресурс ломает её |
| Браузер (Playwright) | `npm run test:e2e` | собирает игру в режиме e2e (как production + тестовый хук) и отдаёт под `/Geometry-of-love/`; проекты `desktop` 1280×720 и `mobile` Pixel 7 |
| Всё сразу | `npm run check:all` | всё перечисленное |

Хук Claude Code после каждой правки `.ts` запускает typecheck, а для `game/src/content/` ещё и валидатор контента.

## Что покрывают браузерные тесты сейчас
- **Концовка 1**: отказ от установки в главе 1.
- **Концовка 3, вся игра**: уроки приложения и мини-игра № 2 (с нерешаемой задачей и блокировкой), № 3 «Предел измерения» и № 4 «Системные файлы» проходятся по-настоящему, через интерфейс; № 1 и № 5 (на реакцию) — через тестовый хук. Проверяются хабы Песочницы и архива, стёртое имя в журнале, фаза E, «Продолжить» после концовки, отсутствие ошибок консоли и 404.
- **Концовка 2**: выбор «остаться» в главе 9; по пути измеряются пропорции всех 4 поз Мелоди (кроме кадров с сюжетным искажением).
- Журнал и меню не продвигают сюжет.
- Ручное сохранение переживает перезагрузку страницы и загружается на ту же реплику.
- Повреждённое сохранение показывается как повреждённое, загрузить его нельзя.
- Настройки сохраняются после перезагрузки.

Скриншоты каждого этапа: `SHOTS_DIR=/абсолютный/путь npm run test:e2e`.

## Как добавлять тесты
- Логику (рантайм, новый шаг, расчёты мини-игры) покрывай unit-тестом в `tests/unit/`. Логику эпизода выноси в чистые экспортируемые функции.
- Путь игрока покрывай e2e-тестом в `tests/e2e/`. Используй `data-testid` и доступные имена (`getByRole`), а не CSS-классы. Помощник `advanceUntil` листает диалог до нужного элемента.
- На каждую исправленную ошибку пиши тест, который падал до исправления.
- Не пиши тесты на несуществующие механики.

## Ручная проверка перед релизом
Запусти `npm run build`, затем `npx vite preview --base /Geometry-of-love/` и открой игру. Проверь на широком окне и на узком (или в эмуляции телефона):
- [ ] Новая игра запускает первую сцену. «Продолжить» восстанавливает последнее сохранение.
- [ ] Имя и реплика читаются, печать ускоряется кликом, длинная реплика прокручивается.
- [ ] Фон, персонажи и смена поз работают; спрайты не растянуты, края пикселей чёткие.
- [ ] Auto, Skip (в режимах «прочитанное» и «всё»), журнал, скрытие интерфейса, быстрое сохранение и загрузка.
- [ ] Выборы ведут в нужные ветки, двойной клик не делает двойной переход.
- [ ] Мини-игра не пропускается при неудаче, повтор работает.
- [ ] Сохранить → обновить страницу → загрузить: реплика, сцена и переменные те же.
- [ ] Перезапись и удаление слота спрашивают подтверждение.
- [ ] Настройки меняют поведение и сохраняются.
- [ ] В консоли нет ошибок, во вкладке Network нет 404.
- [ ] После merge: workflow «Publish build to main» зелёный, «pages build and deployment» завершился, https://monskov1-gif.github.io/Geometry-of-love/ открывается и спрайт виден.

## Известные ограничения проверок
- Звука в игре нет, поэтому и тестов звука нет.
- Скриншоты автоматически не сравниваются (визуальной регрессии нет). Их смотрит человек или агент.
- Проверяется только Chromium. Firefox и Safari можно добавить в `playwright.config.ts` (`devices['Desktop Firefox']`, `devices['iPhone 13']`), но для этого нужны их браузеры.
