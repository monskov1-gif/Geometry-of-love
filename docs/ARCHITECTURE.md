# Архитектура

Стек: **Vite 8 + TypeScript 7 (strict), без UI-фреймворка и игрового движка.** Интерфейс новеллы сделан на DOM/CSS, мини-игры — на DOM или Canvas 2D. Почему именно так, объясняет [DECISIONS.md](DECISIONS.md).

## Слои и зависимости

```
content  ──►  core  ◄──  ui  ──►  platform
   │                      │
   └──► episodes ◄────────┘
```

| Слой | Папка | Ответственность | Может импортировать |
|---|---|---|---|
| core | `game/src/core` | Модель сценария, рантайм, условия/эффекты, формат сохранений, валидатор. **Без DOM**: тестируется в Node. | только core |
| content | `game/src/content` | Данные игры: сцены, персонажи/спрайты, фоны, переменные, концовки, задачи. | core, episodes (реестр), assets |
| episodes | `game/src/episodes` | Мини-игры и интерактивные эпизоды по контракту `EpisodeDefinition`. Сюжетного состояния не трогают. | content (свои данные), ui/dom |
| platform | `game/src/platform` | Хранилище (localStorage с запасным вариантом в памяти), настройки, мета-прогресс, клавиатура, загрузка картинок. | core (типы) |
| ui | `game/src/ui` | Экраны и компоненты на DOM. Отображают `Presentation`, вызывают методы рантайма. | всё выше |
| styles | `game/src/styles` | Токены (`tokens.css`), базовые компоненты, экраны, эпизоды. | — |

## Сценарий

Сцена — это массив шагов (`core/types.ts → Step`). Для удобной записи есть помощники из `core/script.ts`:

| Шаг | Блокирующий | Назначение |
|---|---|---|
| `say` | да | реплика; `kind`: speech, narration, thought, system, error, corrupted, memory |
| `choice` | да | варианты с `id`, `effects`, `goto`, `condition`, `whenUnavailable: 'hide' \| 'disable'` |
| `episode` | да | обязательная мини-игра или интерактивный эпизод; продолжение только после `completeEpisode()` |
| `ending` | да | концовка; разблокируется в мета-прогрессе |
| `show` / `hide` | нет | персонаж, поза, позиция left / center / right |
| `background` / `space` | нет | фон; пространство (reality / app / game / code) и визуальная фаза A–E |
| `effects` | нет | `setFlag`, `relationship +n`, `trait +n` |
| `branch` / `goto` / `label` | нет | переходы; цель записывается как `"scene"` или `"scene#label"` |

`StoryRuntime` (`core/runtime.ts`) сам выполняет неблокирующие шаги и всегда останавливается на блокирующем. `present()` возвращает то, что нужно показать. Действий у рантайма три: `advance()`, `choose(id)`, `completeEpisode()`. Вызов не к месту бросает `StoryError`, и UI показывает эту ошибку. Защита от бесконечных `goto` срабатывает на 10 000 шагов.

`validateStory()` (`core/validate.ts`) статически проверяет весь сценарий: цели переходов, метки, персонажей и позы, фоны, эпизоды, концовки, объявленность переменных, завершённость сцен. Проверка входит в `npm test`, поэтому битая ссылка в сценарии ломает CI, а не прохождение.

## Состояния (разделены)
- **Сюжет**: `StoryState`. Позиция, flags, relationships, traits, история решений, сцена (фон, пространство, фаза, персонажи), концовка. Это единственное, что сохраняется.
- **UI**: в `GameScreen`. Auto, Skip, скрытие интерфейса, открытые панели. В сохранения не попадает.
- **Сессия/ресурсы**: `platform/assets.ts` (кэш и ошибки загрузки), время игры.
- **Мета-прогресс** (`platform/meta.ts`): прочитанные реплики (для Skip) и открытые концовки. Ключ `gol:meta`.
- **Настройки** (`platform/settings.ts`): ключ `gol:settings`.

## Сохранения
Ключи `gol:save:auto`, `gol:save:quick`, `gol:save:slot-1..6`. Формат `SaveData`: `schema`, дата, время игры, название сцены и глава, `StoryState`, последние 200 строк журнала. `SaveStore.read()` никогда не бросает исключение. Он возвращает `ok`, `empty` или `corrupted` с причиной. Если сохранение ссылается на удалённую сцену, конструктор рантайма бросает ошибку, и игрок видит сообщение о несовместимости.
Автосохранение пишется только в слот `auto`: при входе в новую сцену и после успешной мини-игры. Ручные слоты оно не трогает.
Ограничение: сохранения хранятся в localStorage браузера и пропадут при очистке данных сайта или на другом устройстве. Облачных сохранений нет (GitHub Pages — статический хостинг).

## Ввод
`platform/input.ts` — стек слоёв. Экран или панель кладёт свой обработчик, и действие получает только верхний слой. Поэтому открытый журнал или меню не продвигает диалог. Клавиши определяются по `KeyboardEvent.code`, так что A/L/H работают и на русской раскладке. Двойной выбор блокируется в панели выбора. Клик во время печати текста сначала показывает реплику целиком.

## Эпизоды (мини-игры и интерактивные кат-сцены)
Контракт описан в `episodes/types.ts`: `create(ctx) → { run(): Promise<outcome>, destroy() }`. Хост (`ui/episode-host.ts`) показывает карточку с целью и управлением, запускает эпизод и при неудаче предлагает «Попробовать снова». Рантайму сообщается только успех. Чистую логику эпизода (например, `stepWalk`) экспортируй отдельно и покрывай unit-тестами.
Сейчас реализованы:
- `geometry-quiz` — геометрические задачи (числовой ответ или выбор варианта, чертёж в SVG на тетрадном листе). Задумана как основа для мини-игры №2 и вводных задач приложения.
- `horizontal-walk` — движение только влево-вправо к отметке, Canvas 2D в низком разрешении с чёткими пикселями. Это каркас интерактивных эпизодов вроде побега Дамео в Песочницу.

## Спрайты и фоны
`content/characters.ts`: у каждой позы есть `kind: 'sheet'` (лист, прямоугольник кадра, линия среза бюста) или `kind: 'placeholder'`. Исходные листы не нарезаются. `ui/stage.ts` показывает кадр через `background-position`, сохраняя пропорции и `image-rendering: pixelated`. Все позы одного персонажа масштабируются от общей `referenceHeight`, поэтому размер пикселя у них одинаковый. Линия среза бюста стоит на верхнем крае окна диалога.
Картинки импортируются через Vite. Отсутствующий файл ломает сборку, а ошибка загрузки во время игры показывает надпись на месте спрайта и всплывающее сообщение.
Фоны (`content/backgrounds.ts`) пока все CSS-заглушки в палитре своего пространства. Будущий 3D/2.5D-рендер (см. DECISIONS) подключается внутри `Stage` и ничего не меняет в сценарии.

## Пути и GitHub Pages
Корень Vite — `game/`, сборка идёт в `dist/`, `base: './'`. Все URL в сборке относительные, поэтому одна и та же сборка работает локально, по адресу `/Geometry-of-love/` и под любым другим подпутём. Браузерные тесты гоняют сборку именно под `/Geometry-of-love/`.

## Как расширять
- Новая сцена → навык `/new-scene`.
- Новая механика или мини-игра → навык `/new-mechanic`.
- Новый персонаж или поза → запись в `content/characters.ts` (кадр задаётся по реальному листу, проверка `content.test.ts` следит за границами).
- Новый фон → `content/backgrounds.ts` (+ стиль или изображение).
- Новая переменная → `content/variables.ts` со `status` и источником. Качества Дамео добавляются только после одобрения автором.
